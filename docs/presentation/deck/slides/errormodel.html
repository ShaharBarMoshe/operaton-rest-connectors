ERROR HANDLING IN THE MODEL

One event subprocess catches every REST error

Catch-all start

An error start event with no error code catches any BPMN error from any task, including all 5 parallel GETs.

Route by code

The code lands in errorCode, the response body in errorMessage; a gateway picks the end event.

Specific first

A boundary event on a task (HTTP_404 on GET user) still wins.

The subprocess is interrupting: the first error cancels the rest of the instance, so in the fan-out no POST is sent after a failed GET. All three models have it. The end event shows in history which kind of error ended the instance.
