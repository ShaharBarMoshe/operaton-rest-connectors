EXAMPLE 2 · GET WITH PARAMS

A params schema becomes the URL and headers

paramsSchema (shortened)

{"type": "object", "properties": {
 "userId": {"type": "integer",
  "x-in": "path",
  "x-expression": "userId"},
 "fields": {"type": "array",
  "x-in": "query",
  "default": ["contact","preferences"]},
 "filter": {"type": "object",
  "x-in": "query", "properties": {
   "theme": {"x-source":
    "/user/preferences/theme"}}},
 "X-Tenant": {"type": "string",
  "x-in": "header", "default": "acme"}}}

url

${apiBaseUrl}/users/{userId}

→ request sent

GET /users/1042
 ?fields=contact
 &fields=preferences
 &filter.theme=dark
X-Tenant: acme
Authorization: Bearer eyJ…

Arrays repeat the param, objects become name.child; values are strictly URL-encoded (+ → %2B).

The path variable comes from an expression, the query array from a default, the filter from a JSON pointer into the merged sources and the header from a default. The same schema also validates: a missing userId would stop the call with REQUEST_INVALID.
