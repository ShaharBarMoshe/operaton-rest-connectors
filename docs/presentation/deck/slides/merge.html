Two objects + one schema = the body

currentUser (GET result)

{"user": {
 "id": 1042,
 "name": "Maya Lin",
 "contact": {
  "email": "maya.lin@…",
  "phone": "+1-555-0192"},
 "preferences": {
  "theme": "light",
  "notifications": {
   "email": true,
   "sms": false}}}}

userChanges (start var)

{"user": {
 "contact": {
  "phone": "+1-555-0148"},
 "preferences": {
  "theme": "dark",
  "notifications": {
   "sms": true,
   "push": true}},
 "roles": ["editor",
  "reviewer"]}}

→ request body

{"user": {
 "id": 1042,
 "name": "Maya Lin",
 "contact": {
  "email": "maya.lin@…",
  "phone": "+1-555-0148"},
 "preferences": {
  "theme": "dark",
  "notifications": {"email":
   true, "sms": true,
   "push": true}},
 "roles": [ … ]}}

sources = currentUser, userChanges · later source wins · the “merged user” schema keeps only known fields, coerces types and checks required ones.

This is the original example from the requirements. currentUser comes from a GET, userChanges is a start variable. Orange marks what the second object changed or added. The schema then drops anything it does not know, for example an internalScore field from the API.
